# v1.0.6 迁移说明

> Breaking change：`isDev`、`isInt`、`isProd` 已从 `rn-expo-template-kit` 根入口移除。
> `template:update` 只更新依赖，不会覆盖已有项目源码，以下步骤需要手动完成。

## 1. 更新依赖

```bash
npm run template:update -- v1.0.6
```

## 2. 增加项目环境入口

把新版本的 `template/src/config/environment.ts` 加入项目
`src/config/environment.ts`，并把环境判断导入改为：

```diff
- import { isInt } from "rn-expo-template-kit";
+ import { isInt } from "@/config/environment";
```

`isDev` 和 `isProd` 同样从 `@/config/environment` 导入。项目中的 API base URL、Logger、
Backstage 和 Reactotron 配置也应通过该文件读取，不要让 `node_modules` 中的共享包读取
项目 `.env`。

确认项目 `tsconfig.json` 中的别名指向 `src`：

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"],
      "@/assets/*": ["./assets/*"]
    }
  }
}
```

共享的默认 `requestClient`、`request`、`get`、`post` 等别名也不再自动读取
`EXPO_PUBLIC_API_BASE_URL`。需要 base URL 的项目应在 service 层显式创建客户端：

```ts
import { createRequestClient } from 'rn-expo-template-kit';

import { apiBaseURL } from '@/config/environment';

export const api = createRequestClient({ baseURL: apiBaseURL });
```

后端使用 `{ code, msg?, data? }` 业务包裹时，在项目 client 中显式设置对应的
`successCode`，例如 `successCode: "10000"`；未设置时请求器会原样返回 JSON，不猜测
后端协议。

原有 `EXPO_PUBLIC_SENTRY_DSN` 仅连接到占位日志分支，并未初始化 Sentry；该包内读取已
移除。需要接入监控服务时，应在项目配置层初始化真实 SDK，不要把项目专用配置放回
共享包。

## 3. 配置 Logger

共享 logger 不再读取 `EXPO_PUBLIC_ENABLE_LOGGER`。在根布局渲染前设置项目配置：

```ts
import { logger } from 'rn-expo-template-kit';

import { isLoggerEnabled } from '@/config/environment';

logger.setConfig({ enabled: isLoggerEnabled });
```

未显式配置时，logger 仅在 `development` 环境默认开启。`logger.create(prefix)` 创建的
子 logger 会持续读取后续的全局配置，不需要重新创建。

## 4. 修正 Backstage 开关

删除 `__DEV__ || process.env.EXPO_PUBLIC_ENABLE_BACKSTAGE === "true"`，改为从项目环境
入口导入：

```ts
import { isBackstageEnabled } from '@/config/environment';
```

显式 `false` 现在可以在开发 bundle 中关闭 Backstage；显式 `true` 可以在批准的诊断
构建中开启。未配置时只在开发 bundle 默认开启。

## 5. 修正 Reactotron

`src/config/reactotron.native.ts` 应从 `@/config/environment` 导入
`isDev`、`isInt` 和 `reactotronHost`：

```ts
const shouldConnect = isDev || (isInt && Boolean(reactotronHost));
const connectionOptions = reactotronHost
  ? { host: reactotronHost, name: 'Expo App' }
  : { name: 'Expo App' };
```

Development 可将 host 留空，由 Reactotron 从 Metro bundle 地址推导。INT Release 必须
设置电脑局域网 IP，否则不会连接：

```env
EXPO_PUBLIC_REACTOTRON_HOST=192.168.1.20
```

Reactotron Desktop 需监听 `9090`；真机和电脑必须网络互通，防火墙需允许该端口。
Production 与 Web 不连接 Reactotron。

## 6. 补齐环境文件

确保 `.env.development`、`.env.int`、`.env.production` 和 `.env.template` 包含：

```env
EXPO_PUBLIC_APP_ENV=development
EXPO_PUBLIC_API_BASE_URL=
EXPO_PUBLIC_ENABLE_BACKSTAGE=false
EXPO_PUBLIC_ENABLE_LOGGER=false
EXPO_PUBLIC_REACTOTRON_HOST=
```

按环境调整值：Development 默认将 Logger、Backstage 设为 `true`；INT 和 Production
默认设为 `false`。`.env.template` 仅是字段清单，不会自动加载。EAS Build 应在对应
EAS Environment 或 build profile 中注入这些变量。

`EXPO_PUBLIC_*` 是会进入客户端 bundle 的公开构建配置，不能存放密钥。修改后先完整
Reload；只有确认 Metro 缓存异常时才执行 `npx expo start --clear`。

## 7. 验证

```bash
npm run typecheck
npm run lint
```

随后人工确认：

1. Development 的 Logger、Backstage、Reactotron 均按配置工作。
2. INT Release 只有填写可访问的局域网 host 后才连接 Reactotron。
3. Production 的 Logger、Backstage、Reactotron 均关闭。
