# v1.0.8 迁移说明

v1.0.8 增加请求中间件，修正带路径的 `baseURL` 拼接，并将业务响应成功码改为由项目
显式配置。新生成项目会创建项目拥有的 `src/services/api.ts`；已有项目需手动增加该文件。

## 更新依赖

```bash
npm run template:doctor
npm run template:update -- v1.0.8
```

## 创建项目请求客户端

在生成项目中新增 `src/services/api.ts`：

```ts
import { createRequestClient, type RequestConfig } from 'rn-expo-template-kit';

import { apiBaseURL } from '@/config/environment';

export const apiRequestConfig = {
  baseURL: apiBaseURL,
  timeoutMs: 30_000,
  successCode: '10000',
} satisfies RequestConfig;

export const api = createRequestClient(apiRequestConfig);
```

按产品后端协议调整 `successCode`。未设置该字段的共享请求器会直接返回 JSON，不再猜测
`{ code, msg?, data? }` 是否是业务包裹。页面通过 `@/services/api` 发起请求，认证刷新、
拦截器和重试等产品规则也保留在这个项目文件中。

## 可选中间件

需要覆盖请求前、响应后和错误处理时，可注册请求中间件：

```ts
const removeMiddleware = api.use(async (context, next) => {
  return next({
    ...context.config,
    headers: { ...context.config.headers, 'X-Client': 'mobile' },
  });
});
```

中间件按注册顺序进入、反向退出。再次调用 `next` 会重试其下游请求；受控重试必须由
业务代码显式限制次数。完整约定见 [请求客户端](../request-client.md)。

## 验证

```bash
npm run typecheck
npm run lint
npm test
npm run verify:boundaries
```

随后在生成项目运行 `npm run typecheck` 和 `npm run lint`，并确认相对地址能保留
`EXPO_PUBLIC_API_BASE_URL` 中的路径前缀，业务响应成功时返回 `data`，失败时进入项目既有
的错误呈现路径。
