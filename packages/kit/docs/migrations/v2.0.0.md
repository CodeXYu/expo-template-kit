# v2.0.0 迁移说明

v2.0.0 将共享包从 `rn-expo-template-kit` 更名为 `expo-template-kit`，Gitee 仓库同步改为
`git@gitee.com:yu-guangji/expo-template-kit.git`。

这次变更只调整包名、仓库地址和 import specifier。CLI 命令名 `create-rn-expo-app` 与
`rn-expo-template` 保持不变，因此已有项目的 `template:doctor`、`template:update`、
`template:use-local` scripts 不需要修改。

## 新项目

使用新包名和精确 Tag 创建项目：

```bash
npx --yes \
  --package "git+ssh://git@gitee.com/yu-guangji/expo-template-kit.git#v2.0.0" \
  create-rn-expo-app my-app \
  --app-id com.company.myapp
```

## 已有项目

包名变更会同时影响 `package.json` 的依赖 key 和所有源码 import，必须一起迁移。

1. 先确认工作区干净，并保留当前提交，便于回滚。
2. 替换项目源码中的 import：

   ```bash
   # macOS
   rg -l "rn-expo-template-kit" src | xargs sed -i '' "s/rn-expo-template-kit/expo-template-kit/g"

   # Linux
   rg -l "rn-expo-template-kit" src | xargs sed -i "s/rn-expo-template-kit/expo-template-kit/g"
   ```

   至少确认 `src/config/theme.ts` 中的 `declare module 'expo-template-kit'` 也已更新。
   如果项目在 `src` 之外还有引用，先用下面的命令完整查找，再逐处替换：

   ```bash
   rg -l "rn-expo-template-kit" \
     --glob '!node_modules' \
     --glob '!package-lock.json'
   ```

3. 替换依赖 key：

   ```bash
   npm pkg delete dependencies.rn-expo-template-kit
   npm install "git+ssh://git@gitee.com/yu-guangji/expo-template-kit.git#v2.0.0"
   ```

   也可以在 `package.json` 中手动把依赖 key 改为 `expo-template-kit`，再把值改为上面的
   Git 地址，然后执行 `npm install`。不要手工编辑 `package-lock.json`。

4. 安装并校验：

   ```bash
   npm install
   npx expo install --fix
   npm run template:doctor
   ```

5. 运行项目自身检查：

   ```bash
   npm run typecheck
   npm run lint
   ```

如果 Metro 仍缓存旧包名，先完整 Reload；只有确认是缓存问题时才执行
`npx expo start --clear`。

## 旧包名与回滚

- `v1.x` Tag 和旧的 `rn-expo-template-kit` 仓库需要保留至少一个迁移周期，供尚未升级的
  项目按原地址安装。
- 回滚时把 `package.json` 依赖恢复为旧仓库和旧 Tag，并把源码 import 改回
  `rn-expo-template-kit`，然后重新执行 `npm install`。
- v2.0.0 之后的新功能只发布在 `expo-template-kit` 名下，不再同步旧包名。

## 验证

```bash
npm run template:doctor
npm run typecheck
npm run lint
```

原生依赖没有变化，通常不需要重新预构建；如果项目同时升级了 Expo SDK 或其他原生模块，
按项目既有的原生构建流程重新验证 iOS 和 Android。
